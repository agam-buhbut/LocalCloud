## Behavioral fixes
- **RM-1 (ux)** — `rm` (cli.py:589) and `unshare` delete/revoke irreversibly with no prompt. Add `--force/-f`; without it, `click.confirm("Delete <file_id>? This cannot be undone.")` (and the unshare analog). Confirm prompts go to stderr; `--force` skips. Tests: with `--force` deletes without prompt; without `--force` + declined → aborts, no API call (use CliRunner with input="n").
- **ERR-1 (correctness)** — a wrong key password / missing key file escapes as an uncaught traceback in key commands (cli.py ~505 and the other unlock sites). `KeyStore.unlock` raises `ValueError("Failed to unlock key store")`. Wrap the unlock (or the command bodies) so a wrong password prints a clean `"Error: wrong password or corrupt key store"` to stderr + exit 1, no traceback. Test via CliRunner with a bad password.
- **ERR-2 (correctness)** — hostile/malformed server responses cause uncaught tracebacks in commands lacking a broad fallback (api_client.py ~318 and callers). Ensure each command catches the client exception family (StorageError/CryptoError/AuthError/ProtocolError) AND maps unexpected `httpx`/parse errors to a clean message. Mirror the existing typed-catch pattern already used in upload/download. Test: a CloudClient method given a malformed response surfaces a clean error.
- **STDIO-1 (maintainability)** — progress/status messages (`uploaded chunk i/n`, "Fetching metadata…", etc., cli.py ~352 and download) currently go to stdout. Move them to stderr (`click.echo(..., err=True)`); keep machine-output (e.g. the final file_id, `ls` rows, quota numbers) on stdout. Test: CliRunner `mix_stderr=False` — stdout for a command carries only data, not progress.
- **ORDER-1 (ux)** — commands prompt for the key password + unlock (~1s Argon2) before checking a session exists (cli.py ~504). Reorder: load/validate the session token first; if missing, print "No session — run 'localcloud login'" and exit BEFORE prompting for the key password. Test: a command with no session exits without prompting for a password.
- **VAL-1 (correctness)** — add client-side bounds: `--limit` `click.IntRange(1, 200)`, `--offset` `click.IntRange(0)`, and a filename-length guard before upload. Tests: out-of-range values rejected by Click.
- **TLS-1 (security)** — when `--server` is a non-loopback host over plain `http://`, warn on stderr ("plain HTTP to a non-loopback host — traffic is unencrypted unless this is the WireGuard interface"), the client analog of pentest M-2. Do not block (WireGuard is the transport). Test: warning fires for http://10.0.0.1, not for http://127.0.0.1.
- **FILENAME-doc (docs)** — fix the false docstring on `encrypt_file` (encryptor.py:119): the `filename` param is NOT in the encrypted metadata (it's sent server-visible plaintext, by design) and is currently unused inside `encrypt_file`. Correct the docstring to say so; if the param is truly dead, either remove its use-claim or wire it where the caller intends — do NOT change the public signature, just the docstring/behavior note.
